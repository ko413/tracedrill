# giji-trainer

基本情報技術者試験・科目Bの擬似言語を実際に動かし、1文ごとの変数の変化（トレース）を記録する処理系です。
記録から「トレース問題」を自動生成するための土台として作っています。

現在の範囲：字句解析・構文解析・実行器・問題生成・テンプレート検査・テンプレート15本・静的サイトのビルド（練習モードと本番形式）・画面（Streamlit）・テスト（119件）。

無料版は静的サイトとして公開します（`python build.py` → `dist/`）。公開の手順は `PUBLISH.md` にあります。

## 使い方

```python
from giji import run

source = """
○整数型: calc(整数型の配列: data, 整数型: k)
  整数型: sum ← 0
  整数型: i
  for (i を 1 から dataの要素数 まで 1 ずつ増やす)
    if (data[i] mod k = 0)
      sum ← sum + data[i]
    endif
  endfor
  return sum
"""
result = run(source, call="calc({3, 4, 6, 7, 9}, 3)")
result.return_value          # 18
result.values_at(7, "sum")   # [3, 9, 18]  7行目を通るたびの sum
result.count(6, "cond")      # 5           6行目の条件判定の回数
```

静的サイトを作る：`pip install -r requirements.txt` のあと `python build.py`、確認は `python -m http.server -d dist`

Streamlit 版を動かす：`pip install -r requirements-app.txt` のあと `streamlit run app.py`

テスト：`python -m pytest`（依存は `pyyaml`・`streamlit`・`pytest`。Streamlit がなければ画面のテストだけ飛ばします）

問題を作る：

```python
from giji.generator import load_template, generate

template = load_template("templates/basic/loop-sum-001.yaml")
problem = generate(template, seed=7)      # 同じ seed なら必ず同じ問題
for q in problem.questions:
    print(q.prompt, q.choices, q.answer)
```

テンプレートを検査する：`python tools/validate_templates.py -n 300`

## ファイルの役割

| ファイル | 役割 |
|---|---|
| `giji/notation/fe-2023.yaml` | 表記の対応表。キーワード・記号・定型句・型名の綴りをすべてここに置く |
| `giji/notation.py` | 対応表を読み込み、不足や綴りの重複を検査する |
| `giji/lexer.py` | 文字列をトークン列にする。綴りは対応表から引くだけ |
| `giji/ast_nodes.py` | 構文木のデータクラス |
| `giji/parser.py` | トークン列を構文木にする（再帰下降） |
| `giji/interpreter.py` | 構文木を実行し、1文ごとに変数の写しを記録する |
| `giji/errors.py` | 行番号つきの例外 |
| `giji/generator.py` | テンプレートから値を抽選し、実行して、設問と選択肢を作る |
| `giji/render.py` | 行番号つきのプログラムとトレース表を HTML にする（画面から独立） |
| `giji/explain.py` | 設問ごとの解説文を、実行の記録から自動で作る |
| `giji/exam.py` | 本番形式の出題。公開問題の体裁（行番号なし・定型文・解答群6〜8個・ａｂの組合せ）で1問を作る |
| `build.py` | 静的サイトのビルド。検査 → 問題の確定 → HTML → 共有用画像 → sitemap → リンク検査 |
| `site.yaml` | サイト名、公開URL、問題数、連絡先、計測タグの設定 |
| `site/` | ページの雛形（Jinja2）、CSS、JavaScript、共有用画像のフォント |
| `content/` | アルゴリズム解説・読み方ガイドなどの原稿（Markdown） |
| `problems/` | 公開する問題の生成結果（プログラム・設問・選択肢・正解・解説・トレース）。一度作ったら書き換えない |
| `app.py` | Streamlit 版の画面（会員版の土台として残している） |
| `templates/` | 問題テンプレート（YAML）。`basic/` が無料版 |
| `tools/validate_templates.py` | 各テンプレートから数百問を作り、出題して問題ないか検査する |
| `tests/` | 構文ごとの単体テストと、代表的なアルゴリズムの実行テスト |

処理の流れは `文字列 → lexer → トークン列 → parser → 構文木 → interpreter → 実行結果とトレース` の一方向です。

## 対応している構文

- 手続・関数の宣言（`○整数型: f(整数型: n)`）、再帰呼出し
- 変数宣言（初期値つき、複数同時）、代入、`return`
- `if / elseif / else / endif`、`while / endwhile`、`do 〜 while`、`for / endfor`（増やす・減らす）
- 演算子：`not + -`（単項）、`× ÷ mod`、`+ -`、`≠ ≦ ≧ < = >`、`and`、`or`
- `a ÷ b の商`、`a ÷ b の余り`（IPA のサンプル問題・公開問題にある書き方）
- `mの行数`、`mの列数`（二次元配列）
- 配列：`{1, 2, 3}`、`{{1, 2}, {3, 4}}`、`{}`、`{n 個の 0}`、`a[i]`、`a[i, j]`、`aの要素数`、`aの末尾に x を追加する`
- `x を出力する`、注釈（`//`、`/* */`）

未対応（次の版）：クラスとメンバ参照、`未定義` / `未定義の値`、`大域:` の変数、文字列操作。
いずれも本試験の公開問題に出てくるので、優先度は高いです。

## 主な設計判断

### 1. 表記を処理系から切り離した
キーワードや記号の綴りを lexer に書かず、YAML の対応表に出しました。
2027年度の制度改定で表記が変わっても、YAML を複製して右側を直せば対応できます。
`tests/test_lexer_parser.py` の `test_notation_can_be_swapped_without_touching_lexer` が、
代入記号と `endif` を別の綴りに差し替えてもコードを触らずに動くことを確認しています。
全角・半角のゆれ（`＋` と `+` など）も同じ表で吸収しています。

### 2. 答えは必ず「実行結果」から作る
問題の正解を人やAIが書くと誤りが混ざります。この処理系では、文を1つ実行するたびに
変数の写し（深い複製）を記録し、設問も解説もその記録から作る前提にしています。
写しを取るのは、後の代入で過去の記録が書き換わらないようにするためです。

### 3. Python の eval を使わない
擬似言語の式は自前の構文解析器と実行器だけで評価します。
テンプレートの制約式も同じ仕組みで評価するので、外から渡された文字列が Python として実行されることはありません。

### 4. 仕様が決まっていない所は、切替え可能にして既定を厳しくした
IPA の「擬似言語の記述形式」は、次の点を全体としては定めていません
（令和8年度の公開問題で確認。配列の要素番号は問題文ごとに「1から始まる」と断られています）。

| 項目 | 切替え | 既定 |
|---|---|---|
| 配列の最初の要素番号 | `array_base`: 0 / 1 | 1 |
| 整数どうしの `÷` | `int_div`: strict / quotient / real | strict |

`strict` は「割り切れるときだけ許し、割り切れなければ誤りにする」動作です。
解釈が分かれる問題を誤って出題しないための既定値です。
`(low + high) ÷ 2 の商` のように「の商」を付けた除算は、どのモードでも商の整数部分を返します。

### 5. あいまいな構文は字下げで決める
- `do 〜 while`：本体の中の `while` 文と、`do` を閉じる `while` は見た目が同じです。
  「`do` と同じ字下げの `while` が終端」と決めました。先読みや後戻りより単純で、説明もしやすいためです。
- 手続の本体：閉じるキーワードがないので、「○の行より深く字下げされた文まで」を本体にしています。

### 6. 無限ループと暴走を必ず止める
実行ステップ数（既定1万）と呼出しの深さ（既定100）に上限を置いています。
自動生成した問題が終わらないプログラムになっても、検査の段階で落とせます。

### 7. 誤りは行番号つきで報告する
範囲外参照、未設定の変数、0除算、型の合わない演算は、すべて行番号つきの例外になります。
テンプレートを大量に検査するとき、どこが悪いかをすぐ特定するためです。

### 8. 仕様が決まっていない計算は、問題に出さない
負の数を含む `÷` と `mod` の結果は IPA の資料に定めがありません。
問題生成では実行器を `negative_divmod="error"` で動かし、そういう計算が1回でも起きた抽選は捨てます。
値の範囲を人が気をつけるのではなく、実行して確かめる方式なので、テンプレートの書き手が見落としても出題されません。

### 9. 「答えが1つしかない」ことを実行で保証する
空欄補充では、誤答の選択肢もすべて実際に動かします。
正答と同じ結果になる誤答が1つでもあれば、その抽選を捨てます。
実際に、二分探索の初版テンプレートは「誤答でも正しく探索できてしまう」ことをこの検査が見つけ、選択肢を作り直しました。

### 10. 行は番号ではなく目印で指す
テンプレートの設問で行を指すとき、行末に `// @add` のような目印を書いて名前で参照します。
行番号を直接書くと、プログラムを1行直すたびに設問がずれるためです。目印は出題時に取り除かれます。

### 11. 誤答は設問の種類ごとに作り、あり得ない値は出さない
初版は「実行中に現れた値」をまとめて誤答の候補にしていたため、実行回数の選択肢に配列の中身が混ざりました。
いまは設問の種類ごとに、学習者が実際に間違えそうな値から作ります。

| 設問 | 誤答の作り方 | 除くもの |
|---|---|---|
| 実行回数 | 正解の±1、ほかの行の実行回数、配列の要素数 | 負の数、どの行の実行回数よりも大きすぎる数 |
| 変数の値 | 同じ変数の前後の回の値、その文を実行する前の値、同じ時点のほかの変数の値 | 正解が0以上なら負の数 |
| 戻り値 | 返した変数が途中で取った値、戻る時点のほかの変数の値 | 同上 |
| 配列が答え | 同じ変数のほかの時点の状態、隣どうしの入替え、逆順 | 要素の組合せが正解と違うもの（交換途中の状態など） |

### 12. トレースしなくても解ける設問は、出にくくする
最大値の位置や二分探索の戻り値は、配列を見るだけで分かります。
設問ごとに `weight`（出題されやすさ、既定1）を書けるようにし、こうした設問は 0.2 に下げています。
どの設問が出るかは種（seed）から決まるので、同じURLなら同じ設問になります。

### 13. 表示を画面から切り離した
行番号つきのプログラムとトレース表は `render.py` が HTML の文字列として作ります。
Streamlit に依存しないので単体でテストでき、将来ほかの画面に載せ替えるときもそのまま使えます。
利用者に見せる文字列はすべてエスケープしています。

### 14. 検索から来てもらうために、静的サイトにした
Streamlit のページは検索に載りにくいので、無料版は問題を事前に作って 1問＝1ページの HTML にしました。
値だけ違うページを大量に作ると低品質と見なされる恐れがあるため、検索対象は1テンプレート10問に抑え、
残りの20問は検索対象外（noindex）にして sitemap からも外しています。
代わりに、アルゴリズムごとの解説ページと、問題ごとに自動で作る解説文でページの中身を厚くしています。

### 15. 一度公開した問題は動かさない
問題は生成結果ごと `problems/<テンプレートID>/<番号>.json` に保存し、以後のビルドでは読むだけにしています。
保存するのは、プログラム、設問、選択肢、正解、解説、トレース表の中身です（HTML ではなくデータ）。
テンプレートや生成器を直しても、公開済みの問題の URL と中身は変わらず、新しく作る問題にだけ反映されます。
見た目（CSS や HTML の雛形）は保存していないので、デザインの変更は全ページに反映されます。
新しい問題を選ぶときは、保存済みの問題と重ならず、まだ出ていない答えを持つものを優先します。
ある問題を作り直したいときは、その JSON を消してビルドします（URL は同じで中身が変わるので、公開後は慎重に）。
GitHub Actions では `--frozen` を付けて動かし、保存されていない問題があればエラーで止めます。
CI で作った問題はリポジトリに残らず、固定されないためです。

### 16. JavaScript が動かなくても読める
解答前に解説を隠すのは、JavaScript が動いたときだけです（`js` クラスが付いたときだけ効く CSS）。
動かない環境や検索エンジンには、解説とトレース表まで含めた全文が見えます。

### 17. 本番形式は、練習モードと同じ値から作る
本番形式（`exam.py`）は、練習モードの設問が持っている正解・行・変数をそのまま使い、体裁だけを公開問題に合わせます。
行は行番号ではなく `/*** α ***/` の目印で指し、問いは「次のプログラム中の…」「次の記述中の…」の定型文、読点は「，」です。
出題の型は5つ（プログラムの空欄、記述の空欄3種、ａとｂの組合せ）で、問題番号ごとに順に回します。
プログラムの空欄は、誤答をすべて実行し、正解と同じ結果になる選択肢を除いてから出します。

### 18. 空欄は、その場で埋める
空欄補充に答えたあと、空欄つきのプログラムを別のプログラムに差し替えるのをやめ、空欄の文字だけを正解に置き換えます。
プログラムの高さが変わらないので、画面が動きません。

## テンプレートの書き方

```yaml
id: loop-sum-001
title: 条件に合う要素の合計
level: 1                  # 1=入門 … 4=本試験相当
access: free              # free / member
array_base: 1             # 配列の最初の要素番号
int_div: strict           # 整数どうしの ÷ : strict / quotient / real
description: 関数 calc は…（問題文の前置き）

params:                   # 抽選する値。上から順に決まる
  data: {type: int_array, length: [4, 6], range: [1, 12]}   # unique / sorted も指定可
  k: {type: int, range: [2, 4]}
  # {type: choice, values: [...]} / {type: element, of: data} /
  # {type: int_matrix, rows: [3, 4], cols: [2, 3], range: [1, 9]} / {type: char_array, length: [6, 9], alphabet: "abc"} もある

constraints:              # 実行前に確かめる条件（擬似言語の式）
  - "${k} < ${data}の要素数"

source: |
  ○整数型: calc(整数型の配列: data, 整数型: k)
    …
        sum ← sum ＋ data[i]   // @add

call: "calc(${data}, ${k})"

quality:                  # 実行後に確かめる「問題の質の最低条件」
  - "result ≠ 0"          # 答えが0でない
  - "count(add) ≧ 2"      # 目印 add の行が2回以上実行される
  - "steps ≦ 60"          # トレースが長すぎない

questions:
  - {type: return_value, weight: 0.2}                        # weight: 出題されやすさ（既定 1）
  # 答えが要素番号のとき: domain: {index_of: data, extra: [0]} で誤答を 1〜要素数（と extra）に限る
  - {type: var_at_line, line: add, var: sum, pass: random}   # pass: 数 / last / random
  - {type: exec_count, line: add}
  - type: fill_blank
    blank: "data[i] mod k ＝ 0"
    distractors: ["data[i] mod k ≠ 0", "i mod k ＝ 0", "data[i] ÷ k の商 ＝ 0"]   # 本番形式で使うには5つ以上
    blank_b: "sum ＋ data[i]"            # 省略可。書くと本番形式でａとｂの組合せ問題になる
    distractors_b: ["sum ＋ i", "sum ＋ 1"]

explanation: |
  …戻り値は ${result} になります。
```

`quality` で使える名前：`result`（戻り値）、`steps`（実行した文の数）、`output_count`、目印の名前（行番号）、
`count(行)`、`true_count(行)`、`false_count(行)`（条件式が真・偽になった回数）。

検査ツールは、誤り（選択肢の重複、正解が選択肢にない、同じ種で別の問題になる、1問も作れない）と、
警告（採用率が20%未満、答えの種類が3未満、記述式になった設問）を報告します。

## 決めた動作（仕様にない部分）

- `and` / `or` は左から評価し、結果が決まったら右を評価しない（短絡評価）
- `for` の終了値と増分は、繰返しに入る前に1回だけ求める
- 配列は手続に複製せずに渡す（呼び出された側の書換えが呼出し元に見える）
- 負の数の「商」は0方向へ切り捨て、`mod` の符号は割られる数に合わせる
- 識別子は英数字と `_` のみ（日本語の変数名は不可）

## 問題の素材について

IPA は公表済みの試験問題について、原則として許諾・使用料を不要としています（留意点の確認は必要）。
このリポジトリのテストは自作のプログラムだけを使っています。
